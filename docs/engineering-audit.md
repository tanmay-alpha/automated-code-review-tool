## 1. Architecture Summary

The Automated Code Review Tool (ACRT) is a self-hostable pull request review automation platform composed of three primary runtimes and two supporting data stores:

```
                                  ┌──────────────────────────────┐
                                  │   GitHub (API, Webhooks)     │
                                  └───────────▲──────────────────┘
                                              │ (1) Webhooks / REST
                                              ▼
┌───────────────────────┐  same-origin  ┌──────────────────────────────┐
│  Next.js Dashboard    │◄─────────────►│  Spring Boot API (Java 21)   │
│  (Node 24, App Router)│  proxy /api/* │  (Control Plane, Security)   │
└───────────────────────┘               └───────────▲──────────────────┘
                                                    │
                   ┌────────────────────────────────┼────────────────────────────────┐
                   │                                │                                │
                   ▼                                ▼                                ▼
      ┌─────────────────────────┐      ┌─────────────────────────┐      ┌─────────────────────────┐
      │  PostgreSQL 16 + Flyway │      │   Redis (Cache & Auth)  │      │  FastAPI ML Worker      │
      │  (Relational Storage)   │      │   (Tokens, Rate Limits) │      │  (Rules & Evaluation)   │
      └─────────────────────────┘      └─────────────────────────┘      └─────────────────────────┘
```

### Key Subsystems & Boundaries

1. **API / Control Plane (`apps/api`)**:
   - Built with Java 21, Spring Boot 3, Spring Security, JPA/Hibernate, Flyway migrations (V1 through V24), and Resilience4j.
   - Sole authority over PostgreSQL persistence and GitHub REST API mutations.
   - Enforces JWT session lifecycle with per-user token versions (`users.token_version`), CSRF origin verification (`OriginVerificationFilter`), bcrypt-hashed API keys, and AES-256-GCM encryption for stored GitHub OAuth tokens and webhook secrets.
   - Orchestrates diff ingestion, asynchronous worker dispatch, and transactional outbox event publishing.

2. **Web Dashboard & Integrations (`apps/web`, `apps/vscode-ext`, `github-action`)**:
   - Next.js 14 (Node 24) dashboard acting as a first-party runtime reverse proxy (`app/api/[...path]/route.ts`) targeting `API_INTERNAL_URL`. Eliminates cross-site cookie blocking on public suffix platforms (e.g., Render) by serving all API endpoints same-origin.
   - VS Code extension (`apps/vscode-ext`) communicating with the API via workspace-relative paths and secret storage.
   - GitHub Action (`github-action`) running on Node 24 runtime to scan diffs and emit non-intrusive annotations on added lines only.

3. **ML Worker & Rules Engine (`apps/ml-worker`)**:
   - Python 3.11 FastAPI service serving deterministic rule-based analysis (`modelVersion: "rule-baseline-v2"`) by default (`MODEL_NAME=none`).
   - Lexical masking engine (`app/code_lexer.py`) suppressing false positives in comments and strings across Python, JavaScript, TypeScript, and Java.
   - Rule guidance generator (`app/finding_guidance.py`) providing structured evidence, remediation, and caveats for all 12 taxonomy rules.
   - Benchmark evaluation harness (`benchmarks/run_benchmark.py`) scoring diff-level detection against 21 PR fixtures.

4. **GitHub Review & Publication Reliability**:
   - Delivery deduplication by `X-GitHub-Delivery` in `processed_webhooks`.
   - Idempotent sticky comment management utilizing hidden author-scoped HTML markers, paginated lookups, and transactional attempt leasing.
   - Head-SHA fencing preventing race conditions from publishing stale findings when new commits are pushed during analysis.
   - Triage carry-forward preserving user dispositions (`dismissed`, `false_positive` with reasons) across re-reviews of unchanged code.

## 3. Webhook & Outbox Failure Analysis

The following failure-analysis matrix details expected recovery and state behavior across webhook delivery, ML worker invocation, and GitHub PR comment publication.

Scenario → state refers to delivery/publication separately where relevant. Retry rows describe their expected intermediate state and eventual success/exhaustion behavior.

| Scenario | Expected state | Test name |
|---|---|---|
| Duplicate delivery id | One completed delivery / one published sticky comment | `duplicateDeliveryIdIsAcceptedOnce` |
| Same head under another delivery id | Redelivery ignored; original completed/published | `sameHeadRedeliveredUnderANewDeliveryIdIsIgnored` |
| New push on already reviewed PR | New delivery completed; existing sticky comment PATCHed | `newPushEditsTheStickyCommentInsteadOfPostingAnother` |
| New commit during old analysis | Old delivery superseded, no stale publication; new head published | `newCommitDuringAnalysisSupersedesTheOldReview` |
| GitHub head newer than database | Analysis completed; publication superseded | `publicationIsSupersededWhenGitHubReportsANewerHead` |
| Head changes during marker lookup | Publication superseded, zero external writes | `headChangingDuringMarkerLookupPreventsTheExternalWrite`, `databaseHeadChangingDuringMarkerLookupPreventsTheExternalWrite` |
| Rate-limited diff fetch | Delivery failed/retry scheduled at reset, no publication yet | `rateLimitedDiffFetchRetriesAtTheReset` |
| Rate-limited publication | Delivery completed; publication pending at Retry-After | `rateLimitedPublicationWaitsForRetryAfterWithoutTouchingTheReview` |
| Revoked token during diff fetch | Delivery dead_letter, PR failed, github_auth_revoked | `revokedTokenDeadLettersTheDeliveryWithAnExplainableReason` |
| Revoked token during publication | Delivery completed, publication failed, review retained | `revokedTokenAtPublicationFailsThePublicationNotTheReview` |
| Missing PR / too-large diff | Delivery dead_letter with typed reason | `diffTooLargeAndMissingPullRequestAreTerminal` |
| GitHub 5xx / IO | Backoff retry, eventually completed/published or exhausted | `githubServerErrorSchedulesARetryWithBackoff`, `serverErrorsAndDroppedConnectionsAreTransient` |
| Crash after DB commit before comment | Durable pending publication becomes published without reanalysis | `crashAfterReviewCommitIsPublishedByThePollerExactlyOnce` |
| Comment succeeds but ack lost | Pending retry then published; POST count one, retry PATCHes marker comment | `lostAckOnCreateIsFollowedByAPatchOfTheMarkerComment` |
| Marker on later comment page | Existing marker PATCHed; no new comment | `markerLookupPagesThroughLongConversations`, `markerLookupFollowsLinkPaginationAndFiltersByAuthor` |
| Marker lookup pagination budget exceeded | Classified retry/failure; never treat incomplete search as absence/create | `incompleteMarkerLookupFailsRatherThanAllowingADuplicateCreate` |
| Another author plants marker | Foreign comment untouched; own sticky comment created | `markerPlantedByAnotherUserIsNeverEdited` |
| Stored summary deleted | Missing id falls back to marker lookup and safe create | `deletedStickyCommentIsRecreated` |
| Competing workers | Exactly one claim, late completion fenced | `competingWorkersGetOneLeaseEach`; Postgres `concurrentPublishersClaimAPublicationOnce`, `onlyOnePublicationPerPullRequestHoldsALease` |
| Expired analysis lease / stale worker | No stale findings committed | `staleAttemptCannotCommitItsReview`; Postgres `reviewFenceBlocksAStaleAttemptWhileTheNewOwnerHoldsTheLease` |
| Expired publisher after marker lookup | Old worker performs no write; recovered attempt publishes | `expiredPublisherStopsBeforeWritingAndRecoveryUsesTheMarker` |
| ML unavailable | Delivery failed with retry, no publication | `unavailableWorkerRetriesTheDeliveryAndPublishesNothing` |
| ML malformed 2xx body | Classified MlWorkerException, no immediate HTTP retry | `review_malformedSuccessBody_isAnMlWorkerFailureWithoutImmediateRetry` |
| ML rejects diff | Delivery dead_letter, no publication | `workerRejectionDeadLettersDeliveryWithoutRetry` |
| Redelivery/recovery after restart | Reclaimed delivery completes and publishes once | `deliveryInterruptedByRestartIsRecoveredAndPublishedOnce` |
| Optional inline reviews / lost ack | One review per head, commit_id pinned, max ten added RIGHT-side lines, marker reuse | `inlineReviewIsPostedOncePerHeadOnAddedLinesOnly` |
| Comments disabled | Analysis completed; publication skipped, no publication GitHub calls | `disabledCommentsSkipPublicationWithoutCallingGitHub` |
| Developer dismissed unchanged code | Dismissed remains dismissed and absent from GitHub summary | `dismissedFindingIsNotResurfacedOnTheNextPush` |
